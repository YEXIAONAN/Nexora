# 权限矩阵（设计）

> 状态：Phase 1 设计。当前代码尚未实现认证与授权，以下规则不是已交付能力。

## 平台角色

| 能力 | ROOT | 平台管理员 | 普通用户 |
| --- | --- | --- | --- |
| 管理平台管理员 | 是 | 否 | 否 |
| 修改/删除 ROOT | 否（ROOT 自身也需受控流程） | 否 | 否 |
| 转移 ROOT 身份 | 仅专用引导/恢复流程 | 否 | 否 |
| 创建团队 | 是 | 是 | 是 |
| 查看所有团队 | 是 | 是 | 否 |

约束：

- `users.system_root` 为唯一真值，ROOT 身份不通过用户名、昵称或团队角色推断。
- `waiting` 只作为初始 ROOT 身份标识；注册同名账号不能获得权限。
- 普通业务接口不得修改 `system_root`、ROOT 内部 ID 或唯一性约束。
- ROOT 操作写入专门审计事件。

## 团队角色

| 能力 | 所有者 | 管理员 | 成员 |
| --- | --- | --- | --- |
| 编辑团队信息 | 是 | 是 | 否 |
| 邀请/移除成员 | 是 | 是（不能移除所有者） | 否 |
| 分配团队角色 | 是 | 是（不能授予所有者） | 否 |
| 创建项目 | 是 | 是 | 否 |
| 查看团队项目 | 是 | 是 | 是 |
| 管理奖金方案 | 是 | 是（需授权） | 否 |

团队角色是 `team_members.role`，同一用户在不同团队可有不同角色。

## 项目角色

| 能力 | 项目负责人 | 项目参与者 |
| --- | --- | --- |
| 编辑项目 | 是 | 否 |
| 管理任务与依赖 | 是 | 受限（仅负责的任务） |
| 指定任务负责人 | 是 | 否 |
| 提交成果 | 是 | 是（作为负责人/协作者） |
| 验收 | 是 | 需被授予验收权限 |

项目角色不能突破团队访问权限。被移出团队后，项目角色立即失效。

## 授权检查顺序

```text
认证身份
  → 资源所属团队（从 URL/路径解析，且与数据库记录一致）
  → 团队成员关系与状态
  → 团队角色
  → 项目成员关系与角色
  → 具体操作权限
  → 资源状态（是否归档、是否终态）
```

规则：

- 授权在后端 Service 层执行，Handler 不重复实现规则，前端隐藏按钮仅用于体验。
- 查询必须带 `team_id`，不能先查资源再判断。
- 跨团队访问返回 404。
- 批量接口逐项校验，任一项越权则整体失败。
- 已移除成员的会话不保留历史敏感数据访问权。

## 必须覆盖的测试（Phase 1）

1. 修改 URL 中的 team/project/task ID 访问其他团队 → 404。
2. 修改请求体中的 `team_id` → 拒绝。
3. 团队管理员尝试提升自己为平台管理员或 ROOT → 403。
4. 注册 `waiting` 用户名 → 不获得任何 ROOT 能力。
5. 被移除成员使用旧会话访问团队资源 → 403/404。
6. 批量接口混入一个越权 ID → 整体拒绝且无部分写入。
7. 导出接口携带其他团队 ID → 拒绝。
8. 归档项目的写操作 → 409/403。

## 会话安全

- 密码使用 Argon2id 或 bcrypt（成本参数经过基准测试）。
- 会话使用 HttpOnly、Secure、SameSite 的短期 Cookie；不把长期高权限令牌放入 localStorage。
- 登录失败限流；会话支持撤销；敏感操作要求重新认证。
- CSRF：SameSite + 自定义头/双提交令牌，按最终方案测试。
