# ADR 0007：贡献治理与数据库完整性

- 状态：Accepted（M1 治理规则已批准；M2 实现/验证另行报告）
- 批准角色：产品负责人
- 批准日期：2026-11-18（Asia/Shanghai）
- 原文记录：本次 Phase 05 M2 正式任务：“批准 M1，启动 M2。”
- 范围：phase-05-design.md §14 的 18 项最终修订治理决策；不扩展到 M3/API、Vue 或奖金。

18 项分别为：10000 整数基点；不自动推断比例；证据分类/禁止输入；受益人回避；提案人不得核定；明确核定授权范围；负责人自身须他人授权；单人独立核定；无人独立则等待；争议范围与代提；无自动失权；结构化身份核验；草案放弃；旧归档兼容；逐案统计与覆盖；综合指数另批；修订重新核定；归档后普通接口禁止补记争议。以上全部 Accepted，详细条件以本次正式任务和最终设计为准。

附加门禁：可核查的实际结果送达；abandoned 不能绕过正式核算；不破坏历史，不覆盖本地未提交文件。ADR 0005 的金额部分仍 Proposed，绝不能因本批准改变其状态。

本地原稿有不一致：放弃草案曾被视作归档完成；通知引用/摘要曾被视作充分送达；同一来源版本的无条件唯一约束会阻止放弃后再修订；旧有效版本在修订时的统计描述冲突。已由正式任务和设计 §18 记录实施澄清，未新增角色换算份额、平台兜底、时限失权或金额规则。

数据库负责复合作用域、真实验收、不可变确认、严格状态与原子指针、实时资格/COI、自动事件/审计和归档约束。SQL 辅助命令统一 Team→Case 锁顺序及 expected_version。M3 仍必须校验会话身份、Team/Project 授权、请求作用域和角色，部署应给应用受限数据库角色；数据库 owner/DDL 权限不属于普通业务调用者。

送达最小证据是收件人持有有效既有会话令牌并明确确认指定核定摘要，保存身份/会话引用、渠道、发送与确认服务端时间及 request_id；不保存原始令牌。当前没有通知发送机制或新 API，人工通知记录保持未满足。只在真实核验后满足归档，不以测试标志或可写 verified 布尔放行。

历史离队成员必须有真实 project_members 历史行；不以可替换 task_collaborators 作为历史依据。正式份额只读取有效确认且无未决争议；修订仅标注，不用最新 Draft 覆盖有效版本。推翻保留确认事实并原子清空有效指针、产生后继草案。
