# ADR 0001：采用模块化单体

- 状态：已接受
- 日期：2026-10-29

## 背景

Nexora 是单实例多团队平台，核心业务需要强一致的事务（任务状态、验收、贡献、奖金合计）。团队规模与流量不足以证明分布式架构的必要性。

## 决策

后端采用模块化单体：单一 Go 进程、单一 PostgreSQL 数据库。业务按模块分包，模块内部按 Handler/Service/Repository/Domain 组织。

## 后果

优点：事务简单、部署与本地开发成本低、权限校验路径集中、调试容易。

代价：模块边界依赖代码审查与包结构约束；未来若需要拆分，先以模块为边界提取。

## 约束

- 不允许跨模块直接写表。
- 不允许把所有逻辑放入 `main.go` 或单个 Handler 文件。
- 不引入消息队列、服务网格或 Kubernetes。
