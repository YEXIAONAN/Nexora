# 开发路线图

## 原则

- 每个阶段形成可验证的纵向闭环，再进入下一阶段。
- 未通过验证的功能不写入“已完成”。
- 权限、事务、审计与迁移在功能实现时同步完成。

## Phase 0：工程基线（已完成）

交付：

- Monorepo 目录与根配置
- Go API：配置校验、结构化日志、请求 ID、统一错误、优雅退出
- PostgreSQL 连接池、goose 迁移、`system_settings` 基线表
- `/healthz`、`/readyz`、`/api/v1/meta`
- Vue 3 工作台外壳、深浅色主题、真实状态页
- OpenAPI 契约与生成类型
- Docker Compose（PostgreSQL + 迁移 + API + Web）
- 备份/恢复/验证脚本
- CI、单元测试与集成测试基线
- 架构、数据库、权限、API、部署与运维文档

验收结果见 [Phase 0 报告](phase-0-report.md)。

## Phase 1：认证与团队权限（工程代号 Phase 02，已合并并验证）

范围：

1. 用户表、密码哈希（Argon2id）、会话 Cookie、登录/退出/会话撤销。
2. ROOT 安全引导：无默认密码；`waiting` 仅作初始标识；不可变 `system_root`。
3. 平台角色与审计事件。
4. 团队 CRUD、成员邀请/移除、团队角色、团队切换。
5. 团队隔离中间件与 Service 层授权。
6. 资格模型：团队成员 ≠ 参赛资格 ≠ 奖金资格。
7. 账号策略（2026-11-17 新增，随方案 B 批准）：不开放公众注册；ROOT 引导 + 授权账号创建 + 内部邀请（ADR 0004 实施细则）。

验收：

- 跨团队 IDOR 测试全部通过。
- 团队管理员无法获得 ROOT。
- 被移除成员的会话无法访问团队数据。
- 登录限流与密码策略测试通过。
- 所有权限变更写入审计表。

## Phase 2：项目与任务（工程代号 Phase 03，已合并 develop c360327）

- 项目 CRUD、项目成员与负责人、里程碑、归档只读。
- 三级任务、父子约束、循环检测、跨项目校验。
- 状态机与转换审计。
- 前置依赖与显式忽略原因。
- 权重进度聚合（仅叶子任务，取消任务剔除）。

验收：状态机与进度计算单元测试、数据库约束测试、并发转换测试。

## Phase 3：成果验收（工程代号 Phase 04，已合并 develop 07f6fa1c）

- 成果版本、附件/链接/PR 证明。
- 提交、验收通过、驳回、重新提交。
- 验收结论绑定具体成果版本。
- 任务时间线。

验收：未验收任务不计入完成；旧验收不能沿用到新版本。

## Phase 4：贡献核算

- 验收后生成贡献记录。
- 自动建议（确定性规则）+ 人工核定。
- 修订保留历史与原因。
- 项目贡献统计。

验收：调整不覆盖历史；未验收数据不进入正式贡献。

## Phase 5：奖金分配

- 方案、资格、事前约定、币种与总额。
- 建议计算、人工调整、成员确认、最终分配表。
- 精确金额、舍入规则、合计校验、并发确认。
- 零贡献、无资格、未分配余额处理。

验收：金额测试覆盖零值、多人、舍入边界与并发；合计不超过可分配金额。

## Phase 6：工作台与可视化

- 首页待办、待验收、逾期、最近成果。
- 列表/看板/甘特/统计视图共享同一数据源。
- 响应式与深浅色完善。

验收：视图间数据一致；无前端硬编码统计。

## Phase 7：通知、导出、归档

- 站内通知、浏览器通知（用户授权后）。
- Excel/PDF/ZIP 导出与权限过滤。
- 项目归档、历史查询、修订留痕。

## Phase 8：系统级验收

- 全量回归、越权测试、并发与事务检查。
- 安全检查、索引检查、前端性能检查。
- 备份恢复演练、部署验证、文档复核。
- 仅报告真实执行结果。
