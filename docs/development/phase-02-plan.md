## 强制安全测试矩阵（19 项，真实 PostgreSQL 集成测试）

### 身份安全

| # | 场景 | 判定 |
| --- | --- | --- |
| 1 | 不存在默认 ROOT 密码 | 引导必须显式提供密码；弱密码/空密码拒绝；代码与迁移无默认凭据 |
| 2 | 普通用户不能修改 system_root | 账号创建/角色接口不接受该字段；直接 API 尝试无效 |
| 3 | 重复 ROOT 引导安全拒绝 | 第二次引导返回已初始化错误，不产生第二 ROOT |
| 4 | 并发引导不能创建多个 ROOT | 并发 BootstrapRoot 仅一个成功（部分唯一索引） |
| 5 | 被撤销会话无法继续访问 | 退出/管理员撤销后旧 Cookie 401 |
| 6 | 登录失败限流有效 | 超限 429；窗口内正确密码也拒绝；成功登录清除计数 |
| 7 | CSRF 防护有效 | 变更请求缺自定义头 403 |

### Team 隔离

| # | 场景 | 判定 |
| --- | --- | --- |
| 8 | 一个用户能加入 Team A 和 Team B | 邀请接受后两侧成员关系成立 |
| 9 | Team A owner、Team B member 权限不同 | permissions 接口与实际操作分别验证 |
| 10 | Team A 角色不能用于修改 Team B | A 的 owner 对 B 无管理权（403/404） |
| 11 | 修改 URL team_id 不可跨团队访问 | 非成员 404 |
| 12 | 修改请求体 team_id 不得绕过授权 | 邀请接受等只认服务端记录所属 Team |
| 13 | 未加入 Team 的用户无法读取该 Team 数据 | 详情/成员/邀请列表 404 |
| 14 | 移除 A 成员资格后原会话立即失去 A 权限，仍可合法访问 B | 同会话逐请求判定 |
| 15 | 团队管理员不能授予自己 ROOT 或平台管理员 | 平台角色接口仅 ROOT；团队角色接口不能产生平台权限（403） |
| 16 | 最后一名 owner 不得被直接移除 | 移除/降级/自我退出均 409（触发器 + 行锁） |
| 17 | 并发成员或角色操作不得破坏权限约束 | 并发降级双 owner 等场景后仍 ≥1 active owner |
| 18 | 权限变更必须产生审计记录 | 角色变更/移除/邀请/平台角色与业务同事务落审计 |
| 19 | 批量操作越权整体失败且无部分写入 | Phase 02 无批量接口；以邀请/成员事务原子性测试覆盖同理事件，批量接口出现时补测 |

补充：waiting 同名普通账号无 ROOT 能力；用户枚举（不存在用户与错误密码同响应）；会话固定（登录签发新令牌）；跨团队邀请接受拒绝；过期邀请 409；重复 pending 邀请 409。

### 测试安全

全部集成测试复用 `internal/testdb` 护栏：`NEXORA_ENV=test`、`NEXORA_TEST_DB_DISPOSABLE=1`、loopback、`nexora_test*` 库名、随机 `nexora_it_` schema 自动清理。禁止连接运行中的 Nexora 开发库、生产库或其他项目数据库。本地开发验证使用独立一次性 PostgreSQL 实例（独立端口/容器，验证后清理），不在运行中的开发库上自动执行新迁移。

## 验收标准（完成定义）

1. ROOT 安全引导有效（无默认密码、并发安全、重复拒绝、审计）。
2. 用户可安全登录/退出；会话支持过期与撤销。
3. Team 与成员管理真实可用；同一用户多 Team 不同角色。
4. 所有团队资源受后端权限约束；两个真实测试 Team 隔离测试通过。
5. 权限变更审计留痕（同事务）。
6. 最小前端完成真实登录、团队切换及成员操作（浏览器 E2E）。
7. 现有工程质量门禁不退化；CI 必要检查全部通过。
8. 代码推送并创建 PR → develop，不擅自合并。

未全部满足时如实报告实际完成范围，不虚报交付。
