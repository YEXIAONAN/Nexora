# Phase 05 M4 贡献工作台使用说明

贡献工作台沿用现有 Team、Project、登录会话与权限。进入项目详情，选择「贡献核算」。普通成员只能看到服务端允许本人查看的案例；Team 管理员、平台管理员和 ROOT 身份不会自动授予贡献核定权。

## 建立案例与手工草案

1. 成果先走原有提交、附件和独立审核流程，正式验收后才出现在「已验收、尚未建立贡献案例」。获授权人员填写原因并建立案例。
2. 在案例页阅读真实成果、审核意见、附件和证据。填写草案说明，再逐人填写份额、贡献依据、说明及分类证据引用。
3. 百分比最多两位小数，例如 `33.33` 对应 `3333` 个整数基点。系统不自动补齐、推荐或计算份额。草案可以不满 100%，提交必须满足服务端完整性要求并严格合计 10000 基点。
4. 尚未确认的草案允许逐条编辑、删除份额，删除也必须填写原因。放弃草案不表示贡献核算已经完成，也不能绕过归档条件。
5. 「最新工作版本」与「正式有效版本」分别展示。修订中的新草案不会覆盖旧有效核定；被替代或被推翻的历史可在案例底部展开。

附件下载沿用原任务读取权限，核定授权不会自动增加附件权限。如无法读取，先由负责人通过现有审核人管理明确授权，核对证据后再核定；前端不会自动扩大权限。

编辑者整理的声明和引用并不等于贡献者本人签署，也不代表材料已经核验。贡献判断由真实业务人员完成。

## 独立核定与授权

「独立核定工作台」显示服务端返回的本人明确授权、授权版本以及逐案符合独立资格的待办。明确授权不免除受益人、提案人、成果作者、任务审核人或已记录利益冲突的回避义务；裁定还须回避原核定者及争议当事人。无人独立合格时继续等待。

项目负责人可授权其他有效项目成员，负责人本人须由有资格的其他人员授权。授权和撤销均填写原因并绑定服务端授权版本。所有请求仍由后端重新授权。

核定前打开案例核对成果证据、草案和旧有效版本，填写操作原因，并勾选「我已理解：正式核定将形成不可变核定历史」。正式确认后不能直接修改核定历史。

## 本人结果与实际收件

核定后，获授权人员在案例中为在队贡献者「准备收件告知」。准备操作不会产生送达证明。贡献者从导航进入「我的贡献结果」，可查看当前团队各可访问项目的具体核定版本、正式份额、说明、核定者和时间、核定 ID、SHA-256 摘要及实际收件状态。

> 确认收到，仅表示你已收到此结果，不代表同意贡献分配。

只有阅读结果、勾选收件说明并独立点击「确认已收到」，才会调用认证 POST。打开页面、刷新、登录和准备告知均不会自动收件。历史版本的收件不能替代新有效版本所需的凭据。没有匹配的真实凭据时始终显示尚无可信收件证据，归档仍可被后端阻止。

## 争议、修订与离队边界

在案例页对正式有效版本填写异议原因；收件不会解决争议。独立裁定人可以维持或推翻，所有裁定及原始核定保留。推翻撤销旧有效结果并进入后续草案；普通修订保留旧有效结果，直到新版本重新独立核定后才显示被替代。v7 的后继草案份额为空，须重新逐人手工填写依据、证据和整数基点，不会自动复制或分配。

「本人异议请求」仅接受调用者已经持有的准确 Team/Project/Case/Version/Confirmation 标识及本人声明。界面只显示受理编号，不返回核验结果或项目数据。获授权人员在正确案例中输入请求编号，核对真实凭据的声明人、版本和原文后，才可按原文代提。

离队成员不能借此读取普通 Team 数据、查看普通贡献结果或代收件。尚未批准离队成员结果披露和送达通道；缺少可信证据时归档继续受阻。

## 错误与上下文切换

- 409 表示状态或版本可能变化：页面重新读取权威数据，不自动重发或覆盖；重新核对后再操作。
- 401 重新登录；403 提示权限或独立性不足；404 表示不存在或当前不可访问；422 检查字段；500 或网络失败显示重试提示。
- Team、Project 或登录身份改变时立即清空敏感状态并取消旧请求。迟到读取和写入响应不能恢复旧数据或刷新新的上下文。
- 提交期间禁用重复操作；未完成的本地输入不会跨团队缓存。
